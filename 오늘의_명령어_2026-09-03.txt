      한 장만 다르면 세트가 깨져 보이므로 네 버튼 모두에 적용
   ③ hover 글로우 — 여기가 이번 세션에서 가장 까다로웠다.

   ⚠ **패널에 그림자를 걸면 안 그려진다.** .stage-col이 슬라이드 아웃 때문에
     overflow: hidden인데 패널이 열을 정확히 채우기 때문. 확인해보니 .stage-panel에
     있던 box-shadow: 0 6px 18px rgba(0,0,0,0.35)도 **한 번도 그려진 적 없는 죽은 선언**
     이었다(hover 강조를 안쪽 inset 링으로 그리던 것도 같은 이유). 그 죽은 선언은 삭제.

   → 해법은 그림자를 **열(.stage-col)** 에 거는 것. 열 자신의 box-shadow는 자기
     overflow에 잘리지 않는다. 열과 패널은 크기가 같으니 결과는 "버튼에서 빛이 퍼진다"와
     똑같다.
       .stage-col:has(> .stage-panel.lobby-panel-active:hover) {
         box-shadow: 0 0 var(--glow-reach) 4px rgba(255, 255, 255, 0.45);
       }
     :has(> ...)로 직계 자식만 보는 이유는, 멀티 열 안에 방 만들기/참가하기 열이
     중첩돼 있어서 안쪽 버튼에 hover할 때 바깥 멀티 열까지 같이 빛나면 안 되기 때문.

   ⚠ 그런데 그 **중첩된 두 열은 자르개가 두 겹**이다(.stage-col-multi의 overflow +
     .multi-inner의 clip-path). 실제로 찍어보니 방 만들기·방 참가하기는 글로우가
     열 사이 간격 쪽(오른쪽)으로만 새어 나오고 나머지 세 방향은 잘렸다.
     → 멀티 단계에 한해 두 겹을 --glow-reach(14px)만큼 연다
        (overflow-clip-margin, 음수 inset()).

   ⚠⚠ **바깥 멀티 열은 hover 중일 때만 열어야 한다.** 늘 열어두면 싱글을 골라 그 열이
      폭 0으로 줄 때 잘려야 할 패널 조각이 화면 오른쪽에 14px 띠로 남는다.
      overflow는 애니메이션 대상이 아니라 hover에 맞춰 즉시 켜지고 꺼진다.
      실제로 싱글 단계까지 들어가 띠가 남지 않는 것을 확인)

참고 — 이번 세션에서 반복해서 부딪힌 함정
══════════════════════════════════════════════
· **Turbopack 낡은 CSS 청크가 또 나왔다.** 이번엔 TSX(이모지 제거·새 아트)는 HMR로
  반영되는데 CSS만 옛 청크가 남아, "코드는 고쳤는데 화면은 그대로"인 상태가 두 번
  발생했다([5], [8]). 브라우저 캐시가 아니라 dev 서버 쪽이므로 새 브라우저로 접속해도
  똑같다. CSS를 고친 뒤 화면이 안 바뀌면 **가장 먼저 이것을 의심할 것**:
    Ctrl+C → rm -rf .next → npm run dev

· **첨부 이미지는 디스크에 저장되지 않는다.** 세션 트랜스크립트
  (~/.claude/projects/<프로젝트>/<세션>.jsonl)에 base64로 들어 있으므로, JSON을 훑어
  type:"image"의 source.data를 꺼내 디코드하면 파일로 복원할 수 있다.
  변환은 루트 node_modules에 있는 sharp를 그대로 쓰면 된다.

· **measureLobby.mjs는 WS 서버(8080)가 떠 있어야 의미가 있다.** 없으면 패널이
  disabled라 폼이 안 열리고, 표의 "카드"·"폼스크롤"이 전부 '-'인 채
  "문제 없음"으로 나온다. 아무것도 재지 못한 것이다.

· **`next start`를 백그라운드로 띄우면 TaskStop으로 죽지 않는 경우가 있다.**
  포트가 EADDRINUSE로 남으므로, 리스닝 PID를 찾아 직접 종료해야 한다:
    Get-NetTCPConnection -State Listen -LocalPort 3200 | Stop-Process -Id $_.OwningProcess

· **overflow: hidden인 부모 안에서는 자식의 바깥 box-shadow가 절대 안 그려진다.**
  이 로비에서 반복해 발목을 잡은 사실이다. 그림자는 **잘리는 쪽이 아니라
  자르는 쪽 요소**에 걸어야 한다.

# /lobby — 로비 배경 에셋

## 들어 있는 것

| 파일 | 크기 | 용도 |
| --- | --- | --- |
| `table_bg.webp` | 2560×1392 / 255KB | 로비 전체 배경 — 네 동물이 둘러앉은 카드테이블 일러스트 |
| `logo.png` | 가로:세로 ≈ 10:3 | 상단 로고 — 투명 배경 "떱카드 T.U.P.D." 엠블럼 |
| `panel_solo.webp` | 768×768 / 94KB | "혼자 놀기" 패널 아트 — 네 동물 vs 로봇(CPU) |
| `panel_multi.webp` | 768×768 / 80KB | "다같이 놀기" 패널 아트 — 네 동물이 테이블에 둘러앉은 그림 |
| `panel_create.webp` | 768×768 / 78KB | "방 만들기" 패널 아트 — 실용신양이 오두막을 짓는 그림 |
| `panel_join.webp` | 768×768 / 75KB | "방 참가하기" 패널 아트 — 셋이 오두막 문을 두드리는 그림 |

두 경로 모두 [`client/lib/lobbyAssets.ts`](../../lib/lobbyAssets.ts) 한 곳에서만 참조하므로,
파일을 바꿀 때는 그 상수만 고치면 된다.

패널 아트는 `background-image`로 깔려 `cover`에 잘린다 — **가운데는 문구(band 형태의 어두운
스크림)가 덮으므로 주인공을 화면 한가운데 두지 말 것.** 양옆·위아래로 배치해야 패널이 어떤
비율로 늘어나도 살아남는다. 정사각형으로 넣으면 어느 쪽으로 잘려도 무난하다.

네 패널 모두 아트가 채워졌다. `globals.css`의 `.lobby-panel-{tone}` 그라디언트는 이미지가
도착하기 전 한 프레임의 바탕으로만 남아 있다.

### 원본 PNG는 git 이력에 있다

원래 배경은 4096×2198 PNG(12.9MB)였다. 매 접속마다 내려받기엔 너무 무겁고 git 이력에도
버전마다 통째로 쌓이므로 WebP로 줄였다(34배 감소, 육안상 차이 없음).
원본이 필요하면 이력에서 꺼낼 수 있다.

```bash
git show b14caba:client/public/lobby/table_bg.png > table_bg.png
```

해상도를 다시 정할 일이 있으면 참고할 실측값:

| 가로 | 용량 | 선명하게 커버되는 화면 폭 |
| --- | --- | --- |
| 1920px | 208 KB | ~1830px |
| 2048px | 211 KB | ~1950px |
| **2560px (현재, 원본 그대로)** | **255 KB** | **~2440px** |

새 그림(2560×1392)은 원본을 줄이지 않고 webp q80으로만 바꿔 넣었다 — 예전 3072px판
(374KB)보다 오히려 가볍다.

배경은 화면을 꽉 채우므로 투명도가 필요 없다. 테이블은 `cover`로 그려져 화면 가로보다
크게 확대되므로(표시폭 ≈ `max(vw, vh × 1.839)`), 위 표의 "커버되는 화면 폭"은 그 점을
감안한 근사치다.

## 안전영역 — 버튼이 캐릭터를 가리지 않게 하는 좌표

버튼·폼은 캐릭터나 카드더미에 걸리지 않도록 테이블 중앙의 **안전영역** 안에만 놓인다.
좌표는 이미지 크기에 대한 **비율**이라 화면 크기가 바뀌어도 항상 테이블 위에 정확히 붙는다.
값은 전부 [`globals.css`](../../app/globals.css)의 `.lobby-table` 블록에 모여 있다.

```css
.lobby-table {
  --table-w: 2560;      /* table_bg.webp 의 실제 픽셀 크기 */
  --table-h: 1392;
  --safe-left: 28%;     /* 실용신양·디자인어를 피함 (원본 x 717) */
  --safe-right: 28%;    /* 상표토끼·특허랑이를 피함 (원본 x 1843) */
  --safe-top: 15%;      /* 위쪽 램프 아래 (원본 y 209) */
  --safe-bottom: 15%;   /* 아래쪽 찻잔 위 (원본 y 1183) */
}
```

배경 이미지를 **다른 구도로** 교체하면 이 6개 값만 조정하면 된다. 컴포넌트 코드는 손댈 필요가 없다.
해상도만 바뀌는 경우에도 `--table-w/h`는 실제 픽셀 크기로 맞춰 두는 편이 좋다(비율만 맞으면
동작은 같지만, 값이 곧 문서 역할을 한다).

### 값을 정하는 법 — 눈대중하지 말 것

**펠트(초록)가 이어지는 구간을 그림에서 직접 재서** 정한다. 새 그림에서 완전히 빈
사각형은 882×882(좌 33.4% / 우 32.2% / 상 17.2% / 하 19.4%)였는데, **그대로 쓰면
1280×900에서 안전영역이 569×571로 줄어 폼이 넘친다**(폼은 738×628을 쓴다).

예전 그림도 카드 부채의 바깥 끝은 UI 밑에 깔고 있었으므로 같은 기준을 맞췄다 —
좌우 28%는 양·토끼가 끝나는 자리이고 카드 부채의 바깥 끝만 살짝 덮는다.
**정했으면 반드시 `measureLobby.mjs`로 세 해상도를 다시 잰다**(교체 후 실측:
1280×900 → 728×630, 1920×1080 → 874×756, 390×844 → 371×591, 문제 0건).

좁은 화면(≤767px)용 좌우 대칭 보정은 **걷어냈다** — 새 배경은 처음부터 좌우가 28%로
대칭이라 할 일이 없다. 세로로 긴 화면에서 안전영역이 화면 밖으로 뻗는 것은
`.lobby-safe`의 `max-width`/`max-height`가 막는다.

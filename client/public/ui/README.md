# /ui — 화면 공통 UI 프레임

로비·게임 어느 화면에서도 쓸 수 있는 장식 프레임(백보드)을 모아둔다.
로비 전용 배경·패널 아트는 [`../lobby/`](../lobby/)에 있다.

| 파일 | 크기 | 용도 |
| --- | --- | --- |
| `back_board.png` | 1024×1024 / 444KB | 폼(혼자 놀기·방 만들기·방 참가하기) 뒤 나무 액자 |
| `corner_tl.webp` | 256² / 19KB | 좌상 귀퉁이 장식 — 잎 + 버섯 |
| `corner_tr.webp` | 256² / 16KB | 우상 귀퉁이 장식 — 잎 + 도토리 |
| `corner_bl.webp` | 256² / 19KB | 좌하 귀퉁이 장식 — 잎 덩굴 |
| `corner_br.webp` | 256² / 20KB | 우하 귀퉁이 장식 — 잎 덩굴 |
| `score_board.webp` | 1376×768 / 47KB | 가로형 백보드(나무 팻말 포함) — 점수판용. **아직 미사용** |

경로는 [`client/lib/lobbyAssets.ts`](../../lib/lobbyAssets.ts) 한 곳에서만 참조한다.

## 액자와 귀퉁이 장식을 한 장으로 합치지 말 것

액자는 `border-image`로 9분할해 어떤 크기에도 늘어나야 한다. 그런데 **모서리 조각은
언제나 `border-width` × `border-width`로 그려진다** — 지금 값으로 26px 남짓이다.
장식을 액자 그림에 합쳐 넣으면 잎·버섯·도토리가 그 26px에 통째로 압축돼 **초록 얼룩**이
된다. 실제로 210px로 합성해봤다가 되돌렸다.

그래서 둘을 분리했다.

```css
.lobby-form-board::before { border: var(--board-edge) solid transparent;
                            border-image: var(--form-board) 58 fill stretch; }  /* 액자 */
.lobby-form-board::after  { background-image: var(--orn-tl), var(--orn-tr),
                                              var(--orn-bl), var(--orn-br);
                            background-size: var(--orn-size) var(--orn-size); }  /* 장식 */
```

장식은 **고정 크기**라 폼이 커지든 작아지든 늘 같은 크기로 또렷하다.
`::after`가 `::before`보다 뒤에 오므로 장식이 액자 위에 얹힌다(z-index -1 / -2).

## `back_board.png`은 **원본 그대로** 둔다

자르기·축소·WebP 변환·장식선 제거를 모두 하지 않았다. 받은 PNG가 알파를 유지한 채
도착해 복원 처리조차 필요 없었다. 그래서 그림에는 바깥 **투명 여백**(상 73 / 좌 61px)과
양피지 안쪽 **장식선**(y≈136)이 그대로 남아 있다.

투명 여백은 `--board-mt/mr/mb/ml`로 처리한다 — 그만큼 `::before`를 **바깥으로 밀어야**
나무가 카드 모서리에 딱 맞는다. 안 밀면 카드 안쪽에 빈 띠가 생기고 귀퉁이 장식이
나무에서 떨어져 뜬다.

**여백이 네 변에서 다르므로 네 값을 따로 준다.** 한 값으로 뭉뚱그리면 위쪽이 22px,
왼쪽이 16px씩 어긋나 액자가 한쪽으로 쏠린다.

```css
--board-slice: 140;                              /* 여백 + 나무 + 둥근 모서리 */
--board-edge: 40px;                              /* 화면에 그릴 두께 */
--board-mt: calc(var(--board-edge) * 78 / 140);  /* 상 78 · 하 67 · 좌 57 · 우 56px */
```

**그림을 교체하면 이 네 숫자를 다시 재야 한다.** 재는 법 — 각 변의 가운데에서
① 알파가 처음 40을 넘는 곳(= 여백 끝) ② 처음 양피지 색이 나오는 곳(= 나무 끝).

## 슬라이스는 필요 이상으로 키우지 말 것

`58`은 실측값이다 — 나무막대(좌 39px / 상 37px)와 둥근 모서리를 겨우 감싼다.
슬라이스에 양피지가 많이 들려 들어가면 그 부분이 변 조각에서는 **압축**되고 가운데
조각에서는 **확대**되어, 둘이 만나는 자리에 양피지 톤이 어긋난 세로·가로 **이음매**가
생긴다(`120`으로 뒀다가 실제로 겪었다).

## `--orn-overhang`은 바깥 여백보다 작아야 한다

장식 레이어는 액자 밖으로 조금 걸치는데(`inset` 음수), 그만큼 스크롤 영역이 넓어진다.
`.lobby-form-wrap`의 padding을 넘으면 `.stage-form`에 스크롤바가 생긴다
(16px로 뒀다가 390×844에서 겪었다). 현재 데스크톱 10px / 모바일 4px.

## 양피지의 장식선은 지웠다

원본 그림에는 나무틀 안쪽 양피지에 가느다란 선이 한 줄 그려져 있다. 밝기 차이가
244 → 235 수준으로 미묘하지만, `border-image`가 슬라이스를 여러 배 압축해 그리는 바람에
화면에서는 또렷한 실선이 되어 "액자가 두 겹"으로 보인다.

가장자리에서 일정 깊이의 띠를 더 안쪽의 깨끗한 양피지로 바꿔치기해 지웠다.
`back_board`는 640² 기준 **44~54px 띠 → 66px 깊이에서 가져옴**, 둥근 모서리(58px 이내)는
건드리지 않는다. **그림을 새로 교체하면 이 선이 다시 생길 수 있으니** 폼을 띄워
제목 바로 위를 확인할 것.

## 알파 복원 기록

대화 첨부로 받은 그림은 트랜스크립트를 거치며 JPEG로 재인코딩되어 **투명 영역이 순수
검정으로 구워져** 있었다. 전역 색상 키를 쓰면 그림 안의 어두운 외곽선까지 뚫리므로,
테두리에서 연결된 어두운 영역만 flood fill로 지우고 경계는 밝기에 비례한 반투명 +
검정 프리멀티플라이 역연산으로 되살렸다. 원본 PNG가 있다면 그대로 넣는 편이 더 깨끗하다.

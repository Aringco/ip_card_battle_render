# /ui — 화면 공통 UI 프레임

로비·게임 어느 화면에서도 쓸 수 있는 장식 프레임(백보드)을 모아둔다.
로비 전용 배경·패널 아트는 [`../lobby/`](../lobby/)에 있다.

| 파일 | 크기 | 용도 |
| --- | --- | --- |
| `back_board.webp` | 1024×1024 / 67KB | 로비 폼 배경 — 기본(규칙 접힘·좁은 화면) |
| `back_board_wide.webp` | 1226×701 / 46KB | 로비 폼 배경 — 게임 규칙을 펼쳐 2열로 넓어졌을 때 |
| `score_board.webp` | 1376×768 / 47KB | 가로형 원본(나무 팻말 포함) — 점수판용. **아직 미사용** |

`back_board_wide`는 `score_board`에서 **왼쪽 아래 나무 팻말을 지우고 액자만 남긴 것**이다.
팻말이 왼쪽 기둥·모서리와 겹쳐 있어 9분할의 모서리 조각에 담기지 않았다(팻말을 담으려면
모서리 조각이 프레임 두께 75px의 네 배인 260×307이 되어야 했다). 지운 자리는 오른쪽 아래
모서리를 좌우 반전해 메웠다 — 투명 영역으로 원본이 비치지 않도록 `dest-out`으로 먼저
지운 뒤 덧댔다.

경로는 [`client/lib/lobbyAssets.ts`](../../lib/lobbyAssets.ts) 한 곳에서만 참조한다.

## 왜 PNG가 아니라 WebP인가

원본은 알파가 있는 PNG였다. 알파를 유지한 채 줄여봤을 때:

| 형식 | back_board | score_board |
| --- | --- | --- |
| 원본 PNG | 1036KB | 876KB |
| 팔레트 PNG | 364KB | 305KB |
| **WebP** | **67KB** | **47KB** |

로비 첫 화면에서 프리로드되는 에셋이라 용량이 곧 진입 대기시간이다.
`table_bg`를 12.9MB PNG → 374KB WebP로 줄인 것과 같은 판단이다.

## 통짜로 늘리지 말 것 — `border-image`로 9분할해 쓴다

폼은 뷰포트마다 세로로 길쭉한 비율(대략 0.7:1)인데 그림은 정사각형이다.
`background-size: 100% 100%`로 통째로 늘리면 **모서리 잎 덩어리가 가로로 눌린다.**
9분할하면 네 모서리는 배율 그대로 두고 변만 늘어난다.

```css
border: 32px solid transparent;
border-image: url(/ui/back_board.webp) 215 fill stretch;
```

슬라이스는 실측값이다 — **모서리 장식이 안쪽으로 뻗는 거리**가 기준이고, 장식 전체가
모서리 조각 안에 들어가야 잘리지 않으므로 그 바깥값을 쓴다.

| 그림 | 슬라이스 | 나무막대 자체 두께 |
| --- | --- | --- |
| `back_board` | 215 | 좌우 104 / 상하 77·66 |
| `back_board_wide` | 190 | 좌우 75·76 / 상하 80·69 |

`fill`이 있어야 가운데 양피지가 배경으로 함께 그려진다.

## 양피지의 장식선은 지웠다

두 그림 모두 나무틀 안쪽 양피지에 **가느다란 장식선**이 한 줄 그려져 있었다.
원본에서는 밝기 차이가 244 → 235 수준으로 미묘한데, `border-image`가 215px 슬라이스를
32px로 **6.7배 압축**해 그리는 바람에 화면에서는 또렷한 실선이 됐다. 나무틀 자체의
윤곽선과 겹쳐 "액자가 두 겹"으로 보여서 지웠다.

지우는 방법 — 선은 가장자리에서 일정 깊이에 있으므로, 그 띠의 픽셀을 더 안쪽의 깨끗한
양피지로 바꿔치기했다(고사리 무늬와 나무틀 윤곽은 건드리지 않는다). 깊이는 그림마다 다르다.

| 그림 | 지운 띠(가장자리로부터) | 가져온 깊이 |
| --- | --- | --- |
| `back_board` | 132 ~ 148px | 162px |
| `back_board_wide` | 76 ~ 94px | 110px |

**그림을 새로 교체하면 이 선이 다시 생길 수 있다.** 폼을 띄워 제목 바로 위를 확인하고,
가로 전체를 가로지르는 실선이 보이면 같은 방법으로 지운다.

## 두 그림은 카드가 아니라 의사요소 두 겹에 그린다

`border-image-source`는 **보간되지 않는다.** 카드에 직접 걸면 규칙을 펼치는 순간
폭은 부드럽게 늘어나는데 그림만 툭 바뀐다. `::before`(세로형)와 `::after`(가로형)를
겹쳐두고 `opacity`를 교대시켜야 넘어가는 동안 자연스럽다.

**다른 구도의 프레임으로 교체하면 이 슬라이스 값을 다시 재야 한다.**
모서리 장식이 안쪽으로 얼마나 뻗는지가 기준이다.

## 두께를 바꿀 때

`--board-edge`(globals.css의 `.lobby-form-board`)가 화면상 액자 두께다.
키우면 위아래로 그만큼 두꺼워져 **폼이 넘친다.** 실측 상한:

| 뷰포트 | 두께 | 카드 높이 | 결과 |
| --- | --- | --- | --- |
| 1280×900 | 32px | 552 | OK |
| 1280×900 | 40px | 568 | ❌ 폼 스크롤 발생 |
| 390×844 | 20px | 528 | OK (바깥 여백 0.5rem일 때) |
| 390×844 | 24px | 561 | ❌ 정확히 10px 넘침 (바깥 여백 1rem일 때) |

바꿨다면 `client/scripts/measureLobby.mjs`로 반드시 다시 잴 것.

## 알파 복원 기록

이 두 파일은 대화 첨부로 받았는데, 세션 트랜스크립트를 거치며 JPEG로 재인코딩되어
**투명 영역이 순수 검정(0,0,0)으로 구워져 있었다**(전체의 21~27%).
전역 색상 키를 쓰면 그림 안의 어두운 외곽선까지 뚫리므로, **테두리에서 연결된 어두운
영역만 flood fill**로 지우고, 경계는 밝기에 비례한 반투명 + 검정 프리멀티플라이 역연산으로
되살렸다. 초록 배경에 합성해 검은 잔여물이 없음을 확인했다.

원본 PNG가 있다면 그대로 넣는 편이 더 깨끗하다 — 경로 상수만 바꾸면 된다.

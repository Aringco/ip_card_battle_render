# /ui — 화면 공통 UI 프레임

로비·게임 어느 화면에서도 쓸 수 있는 장식 프레임(백보드)을 모아둔다.
로비 전용 배경·패널 아트는 [`../lobby/`](../lobby/)에 있다.

| 파일 | 크기 | 용도 |
| --- | --- | --- |
| `back_board.webp` | 1024×1024 / 67KB | 로비 폼(혼자 놀기·방 만들기·방 참가하기) 배경 |
| `score_board.webp` | 1376×768 / 47KB | 가로형 백보드 — 점수판용. **아직 어디에도 쓰이지 않음** |

경로는 [`client/lib/lobbyAssets.ts`](../../lib/lobbyAssets.ts) 한 곳에서만 참조한다.

## 왜 PNG가 아니라 WebP인가

원본은 알파가 있는 PNG였다. 알파를 유지한 채 줄여봤을 때:

| 형식 | back_board | score_board |
| --- | --- | --- |
| 원본 PNG | 1036KB | 876KB |
| 팔레트 PNG | 364KB | 305KB |
| **WebP** | **67KB** | **47KB** |

로비 첫 화면에서 프리로드되는 에셋이라 용량이 곧 진입 대기시간이다.
`table_bg`를 12.9MB PNG → 374KB WebP로 줄인 것과 같은 판단이다.

## 통짜로 늘리지 말 것 — `border-image`로 9분할해 쓴다

폼은 뷰포트마다 세로로 길쭉한 비율(대략 0.7:1)인데 그림은 정사각형이다.
`background-size: 100% 100%`로 통째로 늘리면 **모서리 잎 덩어리가 가로로 눌린다.**
9분할하면 네 모서리는 배율 그대로 두고 변만 늘어난다.

```css
border: 32px solid transparent;
border-image: url(/ui/back_board.webp) 215 fill stretch;
```

슬라이스 `215`는 실측값이다 — 모서리 잎 덩어리가 안쪽으로 약 215px까지 뻗는다
(프레임 나무막대 자체의 두께는 좌우 104px, 상하 77/66px). 잎 덩어리 전체가 모서리 조각
안에 들어가야 잘리지 않으므로 그 바깥값을 쓴다. `fill`이 있어야 가운데 양피지가
배경으로 함께 그려진다.

**다른 구도의 프레임으로 교체하면 이 슬라이스 값을 다시 재야 한다.**
모서리 장식이 안쪽으로 얼마나 뻗는지가 기준이다.

## 두께를 바꿀 때

`--board-edge`(globals.css의 `.lobby-form-board`)가 화면상 액자 두께다.
키우면 위아래로 그만큼 두꺼워져 **폼이 넘친다.** 실측 상한:

| 뷰포트 | 두께 | 카드 높이 | 결과 |
| --- | --- | --- | --- |
| 1280×900 | 32px | 552 | OK |
| 1280×900 | 40px | 568 | ❌ 폼 스크롤 발생 |
| 390×844 | 20px | 528 | OK (바깥 여백 0.5rem일 때) |
| 390×844 | 24px | 561 | ❌ 정확히 10px 넘침 (바깥 여백 1rem일 때) |

바꿨다면 `client/scripts/measureLobby.mjs`로 반드시 다시 잴 것.

## 알파 복원 기록

이 두 파일은 대화 첨부로 받았는데, 세션 트랜스크립트를 거치며 JPEG로 재인코딩되어
**투명 영역이 순수 검정(0,0,0)으로 구워져 있었다**(전체의 21~27%).
전역 색상 키를 쓰면 그림 안의 어두운 외곽선까지 뚫리므로, **테두리에서 연결된 어두운
영역만 flood fill**로 지우고, 경계는 밝기에 비례한 반투명 + 검정 프리멀티플라이 역연산으로
되살렸다. 초록 배경에 합성해 검은 잔여물이 없음을 확인했다.

원본 PNG가 있다면 그대로 넣는 편이 더 깨끗하다 — 경로 상수만 바꾸면 된다.

## UI 아이콘 5종 — 시트에서 잘라 쓴다

### 지금 쓰는 시트 (2026-09-08, 배경 없는 판)

한 장짜리 시트(1698×926, 2행 4열, 8개)에서 필요한 5개만 잘랐다. **이 판에는 글씨가 없고
아이콘만 들어 있다** — 이전 판에는 아이콘 아래에 라벨이 함께 그려져 있어 잘라내야 했다.
라벨은 언제나 HTML로 따로 쓴다(글꼴을 바꾸거나 문구를 고칠 때 그림을 다시 만들지 않아도
되고, 스크린리더도 읽는다).

> ⚠️ **받은 원본은 투명 배경 PNG였지만, 세션 트랜스크립트에는 JPEG로 들어온다.**
> JPEG에는 알파가 없어 투명한 자리가 **검게** 칠해져 도착한다. 그래서 색상 키가 아니라
> **테두리에서 연결된 near-black(max(r,g,b) ≤ 20) flood fill**로 배경을 되찾았다.
> 아이콘 윤곽선도 짙은 갈색이라, 밝기만 보고 지우면 윤곽선까지 뚫린다 —
> "테두리에서 이어진 것만"이 그 둘을 가르는 기준이다.
> 잘라낸 뒤에는 **양피지색 위에 합성해 검은 잔여물이 없는지 눈으로 확인했다**
> (2026-09-05 `corner_tl`에서 이 확인을 빼먹어 검은 타원이 그대로 배포됐었다).

자른 좌표(시트 1698×926 기준, 연결 성분의 경계상자 그대로):

| 이름 | 시트에서의 자리 | left, top, width, height | 그림 |
| --- | --- | --- | --- |
| `icon_start` | 1행 1열 | 53, 53, 382, 375 | 놀이터 위 재생 버튼 |
| `icon_create` | 1행 2열 | 472, 89, 344, 346 | 통나무집 + |
| `icon_cog` | 1행 3열 | 875, 71, 353, 359 | 톱니바퀴 + 렌치 |
| `icon_rank` | 2행 1열 | 64, 449, 338, 397 | 왕관 쓴 토끼 방패 |
| `icon_help` | 2행 4열 | 1289, 486, 358, 359 | 책 + 돋보기 |

여덟 개가 모두 **깨끗한 연결 성분 하나씩**이라, 이번에는 손으로 자른 것이 없다.
안 쓴 셋은 1행 4열(캐릭터 카드), 2행 2열(도토리 가방), 2행 3열(양+토끼 하트)이다.

각 아이콘은 `resize(256, 256, { fit: 'contain' })`으로 정사각 캔버스에 담는다 — 비율이
제각각이라(`icon_rank`는 세로로 길다) CSS에서 정사각형으로 크기를 주려면 이래야 한다.

### 화면에서의 크기 — 두 가지 쓰임이 있다

| | 클래스 | 크기 | 쓰는 곳 |
| --- | --- | --- | --- |
| 글자 옆 작은 그림 | `.ui-icon` | `1.6em` | "게임 규칙" 접기/펼치기 라벨 |
| 그림 자체가 버튼 | `.icon-button` | px (`--icon-btn`) | 게임 시작·방 만들기·설정·게임 방법 |

`.ui-icon`이 `em`인 것은 글자와 같은 줄에 서기 때문이다 — 글씨 크기 설정(⚙️ 5단계)을
바꿔도 아이콘만 따로 놀지 않는다. 반대로 `.icon-button`은 **버튼 그 자체**라 글씨 크기에
흔들리면 안 된다(특히 로비 폼은 세로 여유가 몇 px 단위다). 그래서 px다.

`.icon-button`은 배경·테두리·안여백을 모두 지우므로 윤곽이 배경 그림에 묻힌다.
그래서 상자 그림자가 아니라 **모양을 따라가는 `drop-shadow`**를 건다 — `box-shadow`는
투명한 사각형 상자에 걸려 아무 데도 그려지지 않는다.

**방 만들기 버튼만 요청보다 작다.** 아이콘 원본 256px의 0.6배(154px)를 그대로 쓰면
로비 폼이 스테이지 박스를 넘겨 조용히 스크롤바가 생긴다(1280×900에서 657 > 590).
실측으로 76px(좁은 화면 40px)이 상한이었다 — 자세한 실측표는 `globals.css`의
`--form-icon-btn` 주석에 있다. **이 값을 올리려면 `client/scripts/measureLobby.mjs`로
반드시 다시 잴 것.**

## 빈 나무판 버튼 `btn_plank` (2026-09-08 오후) — 지금 쓰는 것

받은 그림은 흰 배경 위의 나무판 한 장이었다. 배경은 **테두리에서 이어진 near-white
(min(r,g,b) ≥ 232)** flood fill로 지웠다 — 나무 안쪽 밝은 하이라이트가 그 문턱을 넘지
않아 안전하게 갈린다. 그림 위쪽 가장자리에 흐린 워터마크 글씨가 있어서, 남은 덩어리 중
**가장 큰 것 하나만** 취해 떨궈냈다. 잘라낸 판은 950×245(3.88:1)다.
(2026-09-08 하루에 세 번 갈아끼웠다 — 950×245 → 934×239(더 밝고 결이 고운 판) → 다시 950×245.
비율이 3.88~3.91로 거의 같아 아래 9분할 숫자는 매번 그대로 쓸 수 있었다.)

### 9분할로 그린다 — 슬라이스와 테두리 두께의 비율을 맞출 것

버튼마다 글자 길이가 달라(짧은 "준비"부터 긴 "준비 완료 ✓ (누르면 취소)"까지) 판이
그만큼 늘어나야 한다. `background-size: 100% 100%`로 깔면 판 전체가 눌리므로,
**둥근 끝 마구리는 크기를 지키고 가운데 나뭇결만 늘어나는** 9분할을 쓴다.

```css
border-width: 12px 28px;
border-image: url('/ui/btn_plank.webp') 40 95 fill stretch;
```

> ⚠️ `border-image`의 **모서리 조각은 언제나 `border-width` 크기로 그려진다.** 그래서
> 슬라이스와 테두리 두께의 비율이 가로·세로 같아야 마구리가 안 눌린다.
> 가로 95 → 28px (0.295배) / 세로 40 → 12px (0.300배) — 사실상 같다.
> **한쪽 숫자만 고치지 말 것.** back_board에서 겪은 것과 같은 함정이다.

실측: "준비" 428×63, "규칙 적용" 546×61 — 폭이 100px 넘게 차이 나도 마구리는 그대로다.

## 글씨가 그려진 가로 팻말 두 장 (2026-09-08 오전) — 지금은 미사용

`btn_start_bar` / `btn_solo_bar`는 아이콘 5종과 **규칙이 정반대다.**

| | 아이콘 5종 | 팻말 2종 |
| --- | --- | --- |
| 그림 속 글씨 | 없음 | **있음** ("게임 시작" / "컴퓨터와 대전하기") |
| 화면의 라벨 | HTML로 따로 씀 | **쓰지 않음** — `aria-label`·`title`로만 |
| 크기 지정 | 한 변(px) | **가로만**(px), 세로는 `height: auto` |
| 클래스 | `.icon-button` | `.bar-button` |

팻말에 HTML 라벨을 덧붙이면 같은 말이 두 번 보인다. 반대로 크기를 정사각형처럼 한 변으로
주면 3.1:1 그림이 눌린다 — 그래서 `.bar-button`은 `width: 100%` + `max-width: var(--bar-btn)`
로 **가로만** 정하고 세로는 비율을 따라가게 둔다. 상한이 없으면 대기실처럼 넓은 카드에서
팻말이 카드 폭(700px)만큼 커져 키도 226px까지 자란다.

### 어두운 글로우를 걷어낸 방법 — 아이콘과 다른 기준이 필요했다

이 둘도 원본은 투명 PNG인데 세션에는 JPEG로 도착해, 투명한 자리가 **따뜻한 어두운
글로우**(가장자리 max 53 → 팻말 근처 96까지 서서히 밝아짐)로 칠해져 있었다.
아이콘 때 쓴 near-black(≤20) flood fill로는 이 글로우가 전혀 지워지지 않는다.

그래서 기준을 **"밝기 130 이상 = 나무판"**으로 잡고, 테두리에서 이어진 **130 미만**만
flood fill로 지웠다(글로우 최대치가 110 남짓이라 안전하게 갈린다).

> ⚠️ **"가장 큰 밝은 연결 성분"을 고르는 방법은 쓰면 안 된다.** 처음 그렇게 했다가
> `btn_start_bar`에서 **나무테와 "게임 시작" 글씨가 통째로 잘려 나갔다** — 팻말이 짙은
> 나뭇결·윤곽선으로 쪼개져 안쪽 그림 띠가 더 큰 덩어리로 잡혔고, 통나무집 안쪽까지
> 구멍이 뚫렸다. **배경 쪽에서 접근하면** 나무판이 몇 조각이든, 판 안의 어두운 부분이
> 아무리 짙든 그대로 살아남는다.

나무판 바깥의 **짙은 윤곽선**(두 장 모두 약 14px)은 밝기로는 배경과 갈리지 않는다
(윤곽선 49~57 vs 그 바깥 배경 95~100 — 윤곽선이 오히려 더 어둡다). 그래서 밝기가 아니라
**거리**로 되살렸다: 판 바깥으로 거리변환을 돌려 12px까지는 불투명, 14px에서 0으로
부드럽게 끊는다.

잘라낸 결과는 **양피지색과 초록 펠트 두 배경 위에 합성해** 검은 잔여물이 없는 것을
눈으로 확인했다.

| 파일 | 원본에서 잘라낸 상자 | 최종 |
| --- | --- | --- |
| `btn_solo_bar` | `14,68` 1973×623 | 1024×323 |
| `btn_start_bar` | `93,97` 1816×585 | 1024×330 |

## 게임 방법 창 에셋 여섯 장 (2026-09-08)

받은 그림 3장(각 1376~1380×752)에서 잘라냈다.

| 파일 | 크기 | 용도 |
| --- | --- | --- |
| `howto_board.webp` | 1289×652 / 48KB | 게임 방법 창의 판. **9분할**로 늘려 쓴다 |
| `howto_title.webp` | 768×229 / 27KB | 잎 달린 팻말 — "HOW TO PLAY"가 얹힌다 |
| `howto_corner_{tl,tr,bl,br}.webp` | 각 320×277~305 / 12~17KB | 덩굴·버섯 네 귀퉁이 |

원본 세 장은 배경이 **검정/짙은 회색으로 구워진 JPEG**였다. 전역 임계값으로 지우면 그림
안의 어두운 윤곽선까지 뚫리므로, **테두리에서 연결된 배경만** flood fill로 지웠다. 배경은
무채색(r≈g≈b, 밝기 3~33)이고 덩굴 윤곽선은 초록빛이라, `max(r,g,b) ≤ 52 && 최대−최소 ≤ 10`
이라는 "어둡고 무채색" 조건을 함께 걸어 한 번 더 갈라냈다. 경계의 안티에일리어싱 화소는
밝기에 비례해 알파를 낮춰 검은 테두리를 없앴다.

> **제목 팻말은 가장 큰 덩어리 하나만 남겼다.** 원본 오른쪽 아래에 반짝이 표식(✦)이
> 찍혀 있어 그냥 자르면 세로가 488px로 두 배가 됐다. 잎은 팻말에 붙어 있어 같은 덩어리다.
> (귀퉁이 그림에는 이 규칙을 쓰지 않는다 — 조약돌이 일부러 떨어져 있는 별개 덩어리다.)

### 네 귀퉁이는 "공유 캔버스"로 자른다 — 각자 바짝 자르면 안 된다

처음에는 4분할한 뒤 각 조각을 자기 내용 경계상자로 바짝 잘랐다(320×277~305). 그랬더니
조각마다 크기가 달라지고 **원본에서 서로 얼마나 떨어져 있었는지가 사라져, 화면에 얹었을 때
위쪽 둘의 높이가 어긋났다.**

지금은 넷을 **같은 크기 캔버스**(원본 487×360 → 저장 360×266)로 뽑고, 각 조각을 자기가 맡을
모서리에서 **원본과 같은 거리**에 놓는다. 캔버스 크기는 "각 조각이 자기 모서리에서 가장 멀리
뻗은 거리"의 최댓값이다. `background-position: left top / right top / left bottom / right bottom`
으로 얹으면 원본 배치가 그대로 재현되고, `background-size` 하나로 넷이 함께 움직인다.

> 그 대신 그림 안에 빈 여백이 함께 들어 있어, **같은 폭이라도 잎 덩어리는 바짝 자른 그림보다
> 작게 보인다.** 화면 쪽 `--howto-orn` 값은 그 몫(360/299)을 곱해 잡아야 한다.

`howto_board`의 9분할 슬라이스는 **110**이다. 나무 두께 실측은 위 60 / 아래 45 / 좌우 63~64px
이고, 그 위에 모서리 판자가 서로 겹쳐 튀어나온 부분까지 감싸야 해서 그보다 크게 잡았다.
**필요 이상으로 키우지 말 것** — 양피지가 많이 들려 들어가면 변 조각과 가운데 조각의 톤이
어긋나 이음매가 보인다(`back_board`에서 겪었다).

## 월계수·메달 셋은 스프라이트 시트에서 잘라낸 것이다

1024² 시트 한 장(월계수 3종·메달 1·2·3등·나무 팻말·도토리 등)을 받아 필요한 셋만 떼어냈다.
**사각형으로 자르면 이웃 오브젝트가 모서리에 딸려 온다** — 실제로 금메달 오른쪽 위에
도토리 조각이 들어왔다(도토리 덩어리가 `682,356`부터인데 금메달은 `700`까지 뻗어 있다).

그래서 사각형이 아니라 **연결 성분 단위**로 잘랐다. 시트 전체를 8방향 라벨링한 뒤,
경계상자가 대상 영역 안에 **완전히** 들어가는 덩어리만 남기고 나머지는 알파 0으로 지운다.
배경(거대한 흰 덩어리)도 이 규칙에 자동으로 걸린다.

| 파일 | 시트에서의 위치 (x0,y0 ~ x1,y1) |
| --- | --- |
| `laurel_book.webp` | `358,62 ~ 665,317` |
| `medal_1.webp` | `323,424 ~ 700,586` |
| `medal_2.webp` | `406,612 ~ 618,731` |

## 귀퉁이 장식의 검은 칠은 걷어냈다 (2026-09-05)

받은 `corner_*.webp` 네 장에는 **잎사귀 사이 빈틈이 투명이 아니라 검게 칠해져** 있었다.
`corner_tl`은 덩굴 고리 안쪽이 통째로 검은 타원이었고(436px), `corner_br`(97px)·
`corner_tr`(10px)에도 잎 사이에 검은 조각이 있었다. 양피지 위에 얹으니 그대로 검은 얼룩이었다.

윤곽선까지 지우면 안 되는데, 다행히 둘은 색이 확실히 갈렸다.

| | max(r,g,b) |
| --- | --- |
| 검은 칠 | **0 ~ 3** |
| 잎·덩굴 윤곽선 | 70 ~ 145 |

그래서 **30 이하만** 투명으로 바꾸고, 그 경계의 안티에일리어싱 화소(30~90)는 밝기에
비례해 알파를 낮춰 검은 테두리가 남지 않게 했다. 지금은 네 장 모두 30 이하 덩어리가 0개다.

> **`sharp(경로)`로 읽어 같은 파일에 다시 쓰면 Windows에서 잠긴다**(`EPERM`/`UNKNOWN`).
> `fs.readFileSync`로 버퍼에 담아 `sharp(buffer)`로 넘길 것.

> 시트에는 아직 안 쓴 것이 남아 있다 — **동메달 "3"**(`405,760 ~ 618,879`), 좌우 빈 월계수,
> 나무 팻말 2종, 도토리·버섯, 원형 아이콘 2종, 큰 나무 액자. 3인 이상 순위나 배지가 필요해지면
> 같은 방법으로 떼어내면 된다.
>
> **원본 시트는 저장소에 없다.** 첨부 이미지는 디스크에 남지 않고 세션 트랜스크립트에
> base64로만 들어 있다 — 다시 꺼내는 법은 `NEXT_SESSION.md` §4-5에 있다.

## 액자를 쓰는 화면은 셋이다

`back_board.png` + 귀퉁이 장식은 이제 로비 폼만의 것이 아니다.

| 화면 | 컴포넌트 | CSS |
| --- | --- | --- |
| 로비 폼(혼자·방 만들기·방 참가) | `lobby/Field.tsx`의 `FormCard` | `.lobby-form-board` |
| 대기실 | `lobby/WaitingRoom.tsx` | `.board-frame` |
| 게임 결과 창(체력표·행동 통계) | `game/GameEndScreen.tsx` | `.board-frame` |

뒤의 둘은 [`ui/BoardFrame.tsx`](../../components/ui/BoardFrame.tsx)를 쓴다. **액자를 그리는
규칙(아래 9분할 슬라이스·투명 여백 보정·장식 크기)은 `.lobby-form-board, .board-frame`
공유 선언 한 곳에 있다** — 아래 네 숫자를 다시 잴 일이 생겨도 고칠 곳은 하나뿐이다.

`.board-frame`은 장식을 폼보다 작게 쓴다(`--orn-size: 96px`, `--board-edge: 34px`).
폼의 126px은 `zoom: 1.75`가 걸린 값이라 확대 없는 곳에 그대로 쓰면 과하고, 결과 창처럼
키가 낮은 카드(약 210px)에서는 위아래 장식이 서로 닿아 가운데가 잎으로 막힌다.

## 액자와 귀퉁이 장식을 한 장으로 합치지 말 것

액자는 `border-image`로 9분할해 어떤 크기에도 늘어나야 한다. 그런데 **모서리 조각은
언제나 `border-width` × `border-width`로 그려진다** — 지금 값으로 26px 남짓이다.
장식을 액자 그림에 합쳐 넣으면 잎·버섯·도토리가 그 26px에 통째로 압축돼 **초록 얼룩**이
된다. 실제로 210px로 합성해봤다가 되돌렸다.

그래서 둘을 분리했다.

```css
.lobby-form-board::before { border: var(--board-edge) solid transparent;
                            border-image: var(--form-board) 58 fill stretch; }  /* 액자 */
.lobby-form-board::after  { background-image: var(--orn-tl), var(--orn-tr),
                                              var(--orn-bl), var(--orn-br);
                            background-size: var(--orn-size) var(--orn-size); }  /* 장식 */
```

장식은 **고정 크기**라 폼이 커지든 작아지든 늘 같은 크기로 또렷하다.
`::after`가 `::before`보다 뒤에 오므로 장식이 액자 위에 얹힌다(z-index -1 / -2).

## `back_board.png`은 **원본 그대로** 둔다

자르기·축소·WebP 변환·장식선 제거를 모두 하지 않았다. 받은 PNG가 알파를 유지한 채
도착해 복원 처리조차 필요 없었다. 그래서 그림에는 바깥 **투명 여백**(상 73 / 좌 61px)과
양피지 안쪽 **장식선**(y≈136)이 그대로 남아 있다.

투명 여백은 `--board-mt/mr/mb/ml`로 처리한다 — 그만큼 `::before`를 **바깥으로 밀어야**
나무가 카드 모서리에 딱 맞는다. 안 밀면 카드 안쪽에 빈 띠가 생기고 귀퉁이 장식이
나무에서 떨어져 뜬다.

**여백이 네 변에서 다르므로 네 값을 따로 준다.** 한 값으로 뭉뚱그리면 위쪽이 22px,
왼쪽이 16px씩 어긋나 액자가 한쪽으로 쏠린다.

```css
--board-slice: 140;                              /* 여백 + 나무 + 둥근 모서리 */
--board-edge: 40px;                              /* 화면에 그릴 두께 */
--board-mt: calc(var(--board-edge) * 78 / 140);  /* 상 78 · 하 67 · 좌 57 · 우 56px */
```

**그림을 교체하면 이 네 숫자를 다시 재야 한다.** 재는 법 — 각 변의 가운데에서
① 알파가 처음 40을 넘는 곳(= 여백 끝) ② 처음 양피지 색이 나오는 곳(= 나무 끝).

## 슬라이스는 필요 이상으로 키우지 말 것

`58`은 실측값이다 — 나무막대(좌 39px / 상 37px)와 둥근 모서리를 겨우 감싼다.
슬라이스에 양피지가 많이 들려 들어가면 그 부분이 변 조각에서는 **압축**되고 가운데
조각에서는 **확대**되어, 둘이 만나는 자리에 양피지 톤이 어긋난 세로·가로 **이음매**가
생긴다(`120`으로 뒀다가 실제로 겪었다).

## `--orn-overhang`은 바깥 여백보다 작아야 한다

장식 레이어는 액자 밖으로 조금 걸치는데(`inset` 음수), 그만큼 스크롤 영역이 넓어진다.
`.lobby-form-wrap`의 padding을 넘으면 `.stage-form`에 스크롤바가 생긴다
(16px로 뒀다가 390×844에서 겪었다). 현재 데스크톱 10px / 모바일 4px.

## 양피지의 장식선은 지웠다

원본 그림에는 나무틀 안쪽 양피지에 가느다란 선이 한 줄 그려져 있다. 밝기 차이가
244 → 235 수준으로 미묘하지만, `border-image`가 슬라이스를 여러 배 압축해 그리는 바람에
화면에서는 또렷한 실선이 되어 "액자가 두 겹"으로 보인다.

가장자리에서 일정 깊이의 띠를 더 안쪽의 깨끗한 양피지로 바꿔치기해 지웠다.
`back_board`는 640² 기준 **44~54px 띠 → 66px 깊이에서 가져옴**, 둥근 모서리(58px 이내)는
건드리지 않는다. **그림을 새로 교체하면 이 선이 다시 생길 수 있으니** 폼을 띄워
제목 바로 위를 확인할 것.

## 알파 복원 기록

대화 첨부로 받은 그림은 트랜스크립트를 거치며 JPEG로 재인코딩되어 **투명 영역이 순수
검정으로 구워져** 있었다. 전역 색상 키를 쓰면 그림 안의 어두운 외곽선까지 뚫리므로,
테두리에서 연결된 어두운 영역만 flood fill로 지우고 경계는 밝기에 비례한 반투명 +
검정 프리멀티플라이 역연산으로 되살렸다. 원본 PNG가 있다면 그대로 넣는 편이 더 깨끗하다.

빌드 산출물에 복사돼 배포에 실립니다)에서 잘라낸 조각들입니다.

## 다시 자르기

```bash
cd client && node scripts/cutPlaySheet.mjs
```

원본 시트는 **알파가 없는 3채널 PNG**입니다 — 편집기의 체커보드가 픽셀로 구워져
왔습니다. 스크립트가 하는 일은 셋입니다.

1. **체커보드를 지워 투명도를 되살린다.** 전역 임계값("밝은 회색 = 배경")으로 지우면
   그림 안의 밝은 회색(돌·양피지 하이라이트)까지 뚫리므로, **테두리에서 연결된
   것만** flood fill로 지웁니다. 경계 한 겹은 회색기에 비례해 알파를 깎아 흰 테를 없앱니다.
2. **연결 성분 단위로 고른다.** 시트가 빽빽해 사각형으로 자르면 옆 그림의 잎사귀가
   딸려 옵니다(실제로 `board_h` 위아래에 들어왔습니다). 성분이 아닌 화소는 알파 0으로 지웁니다.
3. **경계상자에 바짝 자른다.** `border-image`의 슬라이스는 그림 가장자리부터 재므로
   투명 여백이 끼면 그만큼 어긋납니다.

> ⚠️ 시트를 새로 받으면 경계상자가 전부 달라집니다. 스크립트가 "성분을 못 찾음"으로
> 멈추면 아래 명령으로 좌표를 다시 찍으세요.
>
> ```bash
> node scripts/cutPlaySheet.mjs --list master_sheet.png
> ```
>
> ⚠️ **눈으로 잰 경계상자를 그대로 쓰면 안 됩니다.** 자르기 전에 경계 한 겹의 알파를
> 깎는 보정이 들어가서, 원본을 그냥 훑어 잰 값과 1~2px 어긋납니다 — 실제로 상단 바가
> 그 차이로 "성분을 못 찾음"이 났습니다. 반드시 `--list`로 찍은 값을 쓸 것.

### ⚠️ 가장자리에 남은 띠 — `stripTop`

배경을 지운 시트에 **폭 전체를 가로지르는 불투명한 줄**이 남아 오는 일이 있습니다.
색 보정본(`game_ui_assets_1_cc_nobg`)은 맨 위 6줄이 거의 검은색(alpha 255)으로 왔습니다.

이 줄은 **체커보드가 아니라서 flood fill로 지워지지 않고**, 거기 닿는 조각이 전부
한 성분으로 붙어 버립니다 — 상단 바가 `[0, 0, 2560, 239]`, 곧 시트 전체 폭으로
잡혔습니다. 조각 하나가 유독 거대하게 나오면 이것부터 의심하세요.

시트 정의에 `stripTop: 6`을 주면 **성분을 세기 전에** 그 줄을 지웁니다.
`--list`도 같은 옵션을 적용하므로 목록과 실제 자르기가 어긋나지 않습니다.

```js
{ src: 'master_sheet.png', stripTop: 6, pieces: [ … ] }
```

띠가 몇 줄인지 재는 법 — 줄별로 "불투명한 화소 수"를 세면 띠 구간만 폭 전체(2560)가
나오고 그 아래로 뚝 떨어집니다(여기서는 y 0~5가 2560, y 6부터 36).

> ⚠️ **필요한 만큼만 지울 것.** 이 시트는 그림이 y 6에서 곧바로 시작해 여유가 없었습니다.
> 한 줄만 더 지웠어도 잎 끝이 잘렸을 것이고, 잘린 티는 잘 안 나면서 조각 높이만
> 조용히 달라집니다.

### 되돌린 선택 두 가지 (같은 실수를 반복하지 않기 위해)

* **해설판에 `label_small`을 쓰지 않는다.** 그 그림은 잎이 삐져나온 **위아래 투명
  여백**이 커서, 64px로 눌러 담으면 양피지가 띠의 아래 3분의 2에만 깔리고 **글자 첫
  줄이 그 위 허공에 뜹니다.** `board_h`는 양피지가 그림 높이의 대부분이라 띠 전체가 종이로 덮입니다.
* **사진을 덮는 액자에는 `fill`을 쓰지 않는다.** 가운데 조각까지 그리면 양피지가
  장소 사진을 통째로 덮습니다. `fill` 없이 쓰면 여덟 조각(네 변·네 모서리)만 그려져
  사진 가장자리에 액자만 얹힙니다.

### ⚠️ 액자가 바깥, 그림이 안쪽 — 순서를 뒤집지 말 것

**그림을 상자에 꽉 채우고 액자를 그 위에 덮으면 안 됩니다.** 그러면 그림이 액자
밖으로 비어져 나온 것처럼 보입니다(실제로 그렇게 만들었다가 고쳤습니다).
액자가 상자 가장자리를 차지하고, 그림은 그 **안쪽 사각형**에 들어가야 합니다.

```
액자 클래스   → --frame-inset: <테두리 두께보다 2px 작게>
그림 레이어   → class="play-frame-inset absolute"   (inset-0 이 아니다)
```

`.play-frame-inset { inset: var(--frame-inset, 0); }` 한 줄이고, 액자 클래스가
자기 두께에 맞춰 그 값을 정해 줍니다. **새 액자를 만들 때 이 짝을 함께 둘 것.**

> ⚠️ **`<img>`를 직접 `play-frame-inset`으로 앉히지 마세요.** 절대배치된 **대체 요소**의
> `width: auto`는 네 변(inset)이 아니라 그림의 **내재 크기**로 풀립니다 — `object-contain`이
> 먹지 않고 라벨이 잘립니다(장소 라벨에서 실제로 잘렸습니다). `<div>`로 한 겹 감싸고
> 그 안의 `<img>`에 `w-full h-full object-contain`을 줍니다.

### 상단 바는 늘이지 않는다 — 통째로 확대한다

3분할·9분할은 모서리를 지켜 주지만 **가운데는 어차피 늘어납니다.** 상단 바는 그
가운데에 잎사귀가 박혀 있어, 처음에는 마구리를 "무늬 없는 나뭇결" 앞뒤로 잘라
(1540~1950) 잎만이라도 지키는 방식을 썼습니다. 그래도 결무늬는 1~2배로 눌렸습니다.

지금은 **분할을 아예 걷어냈습니다.** 상자의 비율을 그림의 비율(2502:237)에 맞춰 놓고
`background-size: 100% 100%`로 채우면, 상자와 그림의 비율이 같으므로 어느 폭에서도
**한 점도 찌그러지지 않습니다.**

```css
--beam-w: min(100vw, calc(24vh * 2502 / 237));
--beam-h: calc(var(--beam-w) * 237 / 2502);   /* 높이를 너비에서 뽑는다 */
```

팻말 좌표는 예전 식(`--beam-h × 129/237`)을 그대로 씁니다 — 그 값은 곧
`--beam-w × 129/2502`라 그림 속 비율과 정확히 같은 자리를 가리킵니다.

> ⚠️ 비율을 지키면 **높이가 너비를 따라갑니다** — 32:9처럼 넓고 짧은 화면에서는 바가
> 화면의 40%까지 먹습니다. 그래서 너비에 상한을 뒀습니다: 높이가 24vh를 넘길 만큼
> 넓어지면 **바 자체를 좁혀 가운데 정렬**합니다(눌러서가 아니라 좁혀서 막으므로 비율은
> 그대로). 보통 화면은 이 상한에 닿지 않습니다 — 1600×900에서 상한 폭이 2090px이라
> 100vw가 먼저 걸립니다.

### ⚠️ 마구리가 두꺼운 3분할을 `border`로 그리지 말 것

지금은 상단 바가 분할을 쓰지 않지만, **다른 곳에서 같은 함정을 만날 수 있어 남깁니다.**

3분할 시절 `upper_bar`는 왼쪽 마구리(=팻말)가 `--beam-h`의 2.2배(240px)였습니다.
이걸 헤더 **자신의** `border-left`로 그렸더니, 절대배치 자식의 기준 상자가 부모의
**padding box**라 팻말 글자가 통째로 240px 오른쪽 나무 위에 얹혔습니다 — computed
`left`는 58.86px로 맞았는데 실제 렌더는 299px이었습니다.
`::before`(`inset: 0`)로 옮기면 헤더가 테두리 없는 상자로 남아 padding box =
border box가 되고 좌표가 그대로 맞습니다.

### ⚠️ 이름표 글자가 앉을 자리는 그림 높이의 45%뿐이다

`nameplate.webp`(490×239)의 세로 밝기를 재보면 크림 양피지는 **y 71~179(29.7%~75%)**
이고 나머지는 나무틀입니다. 헤더 안높이 66px 기준으로 쓸 수 있는 세로는 **30px**뿐이라,
두 줄을 `text-base`(15.4px) + `text-xs`(11.5px) = 27px로 잡았습니다.
그보다 키우면 글씨가 나무틀 위로 걸칩니다(실제로 걸쳤습니다).
**글씨를 키우려면 이름표(=헤더)를 먼저 키워야 합니다.**

### ⚠️ 모서리 장식이 개구부보다 크면 `border`로 그리지 말 것

이 액자들은 **모서리 잎 덩어리가 나무 개구부보다 훨씬 큽니다.**

```
frame_square 703×782   나무 74/69 · 바깥여백 51/63 · 개구부 125/132 · 모서리 잎 215
frame_wide  1153×752   나무 71/62 · 바깥여백 34/48 · 개구부 105/110 · 모서리 잎 230
```

9분할의 모서리 조각은 `border-width` 크기로 그려지므로, 잎이 안 눌리려면
`border-width = 슬라이스 × 배율`이어야 합니다. 그런데 `border`는 **내용이 시작하는
자리**이기도 해서, 그렇게 잡으면 내용이 필요 이상으로 밀립니다 — 269px짜리 팀 패널에서
남는 폭이 절반이 됩니다.

**해법** — 액자를 `::after`(`inset: 0`)로 띄워 그립니다. 이 층은 레이아웃에 영향을 주지
않으므로 `border-width`를 순전히 "잎이 안 눌리는 값"으로만 잡을 수 있고, 내용이
시작하는 자리는 판 자신의 `padding`이 따로 정합니다(나무 안쪽 개구부 기준).
잎이 내용 모서리를 살짝 덮는데, 그건 원화 그대로의 모습입니다.

> ⚠️ **배율을 바꾸면 `padding`도 함께 고칠 것.** 둘은 같은 배율에서 나온 짝이라
> 한쪽만 고치면 액자와 내용이 어긋납니다.

### (옛 기록) 액자 안쪽에 흰 띠가 생기면 — `--wood-gap`

**지금 구조에서는 일어나지 않습니다**(액자가 `border`가 아니라 의사요소라서). 다른
곳에서 `border-image`를 쓸 때 같은 함정을 만날 수 있어 남깁니다.

`border-image`는 테두리 띠를 그림의 슬라이스로 채웁니다. 그런데 **그림에서 나무가
차지하는 두께가 슬라이스보다 얇으면 나머지는 투명하게 남습니다.**

```
빈 띠 = border-width × (1 − 나무두께 / 슬라이스)

wf_card   나무 39 / 슬라이스 70 / border 22px → 나무 12.3px, 빈 띠 9.7px
wf_strip  나무 22 / 슬라이스 44 / border 16px → 나무  8.0px, 빈 띠 8.0px
```

그 빈 띠로 **뒤 페이지 배경이 그대로 비쳐** 액자 안쪽에 흰 줄이 생깁니다.
양피지 `::before`가 `inset: 0`, 곧 padding box(띠 **안쪽**)에 있어 거기까지 닿지
못하는 것이 원인입니다.

**해법** — 양피지 층을 `--wood-gap`만큼 **바깥으로** 밀어 빈 띠를 종이로 메웁니다.

```css
.wood-panel::before { inset: calc(var(--wood-gap, 0px) * -1); }
.wood-panel-card  { --wood-gap: 10px; }   /* 9.7px을 올림 */
.wood-panel-strip { --wood-gap:  8px; }
```

이 층은 z-index가 음수라 요소의 테두리 **위에** 그려지므로(CSS 페인트 순서:
배경·테두리 → 음수 z-index 자식) 값이 조금 넘쳐도 나무 안쪽 가장자리를 1px 덮을 뿐
밖으로 새지 않습니다. **셋(두께·슬라이스·나무폭) 중 하나라도 바꾸면 다시 계산할 것.**

### ⚠️ 판 액자의 두께는 **화면 높이를 따라간다** (`--fb-card` / `--fb-wide`)

`.play-bg`에 변수 둘이 있고, 이 값 하나에서 **세 가지가 함께** 나옵니다.

| 읽는 곳 | 계산 |
| --- | --- |
| 액자 테 | `.wood-panel-*::after`의 `border-width` = 변수 그대로 |
| 내용이 시작하는 자리 | `padding` = 테 × (개구부 / 슬라이스) + 10px |
| 좌우 판이 가운데로 파고드는 폭 | `.panel-overlap-*` = 테 × (바깥여백 / 슬라이스)의 두 액자 합 |

**셋을 따로 적으면 반드시 어긋납니다** — 한 배율에서 나온 짝이기 때문입니다. 특히
겹침 폭은 "그림의 투명한 바깥여백"이 그대로 틈이 되는 값이라, 액자를 두껍게 하면
그 틈도 같은 비율로 벌어집니다(2배로 키웠을 때 30px → 56px이 필요했습니다).

```css
--fb-card: clamp(69px, calc(22.1vh - 100px), 138px);   /* 1080→138 · 900→99 · 768→70 */
--fb-wide: clamp(77px, calc(24.7vh - 112px), 154px);
```

**고정 px이 아니라 화면 높이에 건 이유**는 실측으로 드러났습니다. 요청받은 "2배"인
138px을 그대로 고정하니 1080 높이에서는 의도대로였지만, **768 높이에서 팀 패널 안쪽
세로가 151px만 남아** 경험치 네 줄(약 250px 필요)이 잘렸습니다. 액자는 화면이 작아져도
같은 두께를 차지하는데 내용 공간만 줄기 때문입니다. 그래서 768에서 1.4배로 물러나도록
기울기를 잡았습니다(`a·vh + b` 꼴이라야 두 지점을 모두 지납니다 — 순수 비례로는 불가능).

**두께를 다시 바꿀 때는 반드시 `node scripts/measurePlay.mjs`로 1366×768을 함께 볼 것.**
1920만 보면 이 문제가 보이지 않습니다.

### ⚠️ 액자는 내용과 딱 맞물려야 한다

액자와 내용 사이에 크림색 띠가 떠 보인다는 지적을 받았습니다. 그 띠는 두 가지가
겹친 것이었습니다 — ① 판의 안여백(`p-1`/`p-2`), ② **양피지 `::before`의 테두리 두께**.
②를 12 → 6px로 줄이고 ①을 카드판 0 · 팀 패널 3px까지 내렸습니다.

### 장소 칸에는 액자를 두르지 않는다

카드판 자체가 이미 액자에 담겨 있어, 그 안의 네 칸까지 두르면 **나무가 두 겹**이
됩니다. 가안도 장소 칸은 사진만 둡니다. 쓰지 않던 `.play-photo-frame` 규칙은
그 그림(`wf_card`)이 사라지면서 함께 걷어냈습니다.

### 나무테와 양피지는 따로 그려져 있다 — 두 층으로 쌓는다

`frame_sheet.png`의 요령입니다. 시트에 있는 "조합 예시"는 둘을 겹쳐 본 **견본**일 뿐,
그런 파일이 따로 있는 게 아닙니다. CSS에서도 두 층으로 쌓습니다.

```
나무테 … 요소의 진짜 border        → 안쪽 내용이 저절로 테 안에 들어간다
양피지 … ::before가 padding box를 9분할로 채운다
팀 색  … ::after가 그 위에 옅게 얹는다 (--panel-tint)
```

* **나무테에는 `fill`을 쓰지 않습니다** — 쓰면 가운데 나뭇결이 양피지를 덮습니다.
* `isolation: isolate`가 있어야 `z-index: -1`인 두 층이 판 밖으로 새지 않습니다.
* 팀 색을 옛날처럼 `bg-lime-100`으로 깔면 **종이 질감이 죽습니다.** 양피지 **위에**
  옅게 얹는 `--panel-tint`로 바꿔, 종이를 살리면서 어느 팀인지도 읽히게 했습니다.
* ⚠️ 나무테를 자를 때는 **가운데를 뚫어야 합니다**(`hollow`) — 나무가 사방을 막아
  테두리에서 출발하는 flood fill이 안쪽에 닿지 못합니다.

> ⚠️ **액자가 들어오면 안쪽이 그만큼 좁아집니다.** 팀 패널에 좌우 22px씩 액자가
> 들어오자 팀 이름 줄("○○ 기사단 ⭐내 팀")이 잘렸습니다 — 그리드 열을
> `19rem` → `21rem`으로 넓혀 액자가 먹는 폭을 돌려줬습니다.

### 기술 카드 테두리는 그림이 아니라 CSS다

`card_frame.webp`를 9분할로 두르다가 **CSS 그라데이션 테두리로 되돌렸습니다**(2026-09-11).
카드가 217px밖에 안 되는 자리에서 금색 막대가 뭉툭했고, 두께를 줄이면 모서리 곡선까지
함께 작아져 조절할 여지가 없었습니다. CSS는 두께(5px)와 둥글기(10px)를 따로 정합니다.
`card_frame.webp`는 지우지 않고 남겨 뒀습니다.

```css
border: 5px solid transparent;            /* 띠는 투명하게 비워 두고 */
background-image: linear-gradient(…);      /* 그 자리에 금색을 깔아 비치게 한다 */
background-origin: border-box;             /* ← 없으면 테두리에서 이음매가 진다 */
overflow: hidden;                          /* ← 없으면 그림 귀가 둥근 모서리 밖으로 나온다 */
```

**진짜 `border`라서 `--frame-inset`이 0입니다.** 절대배치 자식의 기준 상자는 부모의
**padding box**라, `inset: 0`이 곧 테두리 안쪽입니다 — "액자가 바깥, 그림이 안쪽"이
공짜로 지켜집니다.

> ⚠️ 모서리 장식을 26 → **39px**(1.5배)로 키우자 글자를 두 번 덮었습니다.
> ① 우상단 "레벨 부족" 표시와 긴 효과 문구 → 그 줄을 `top-2`에서 `top-[42px]`로 내림.
> ② 대사 마지막 줄이 **아래쪽** 장식 뒤로 숨음 → 자막 상자의 아래 안여백을
>    `p-3`(9.6px)에서 `pb-[34px]`로 늘림.
> **장식을 키우면 그 크기만큼 글자 자리를 비워 줘야 합니다.**

### 카드는 맞붙지 않고 낱장으로 떨어져 있다

띠(`SkillChoiceBar`)가 칸 사이를 `divide-x-2`로 가르던 것을 걷고 `gap-2 p-2`로 바꿨습니다 —
다섯 칸이 한 덩어리가 아니라 카드 다섯 장처럼 보이게 하려는 것입니다. 카드가 그만큼
작아지므로 `border-radius: 16px`이 또렷하게 읽힙니다.

### 안이 막힌 액자는 가운데를 따로 뚫는다

`card_frame`은 금색 막대가 사방을 둘러싸고 있어 **테두리에서 출발하는 flood fill이
안쪽에 닿지 못합니다.** 그대로 두면 액자 속이 체커보드로 꽉 찬 불투명 판이 되어
기술 컷신을 통째로 가립니다(실제로 막대 두께를 재니 826px이 나왔습니다).
`cutPlaySheet.mjs`의 `hollow: true`가 가운데에서 한 번 더 fill해 비웁니다.

### 귀퉁이 잎이 눌리지 않는 조건

로비의 `back_board`에서는 귀퉁이 장식을 액자 그림에서 **분리**해야 했습니다. 여기서는
분리하지 않아도 되는데, 이유가 있습니다 — **슬라이스가 정사각(90×90)이고 네 변 두께가
같으면**, 모서리 조각은 가로·세로 같은 배율로 줄어들 뿐 눌리지 않습니다.
눌림은 슬라이스가 직사각이거나 변마다 두께가 다를 때 생깁니다.

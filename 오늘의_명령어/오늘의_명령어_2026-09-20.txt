   2 — **초록 막대는 .stage-form이 아니라 카드 안쪽 .lobby-form-scroll의 것이었다.**
     실측 넘침 — 방 만들기 **54px** · 방 참가하기 **9px**(1280x900).
     원인은 --form-zoom 1.35를 세 폼이 함께 쓴 것. 접힌 키가 다르다:
       혼자 놀기    닉네임·팀 이름·규칙                    상한 1.6
       방 참가하기  닉네임·방 코드·자리 선택                상한 1.4 (초대 배너 붙으면 ↓)
       방 만들기    닉네임·팀 이름 2개·자리 선택·규칙       상한 **1.3**
     1.6부터 1.0까지 훑으며 넘침을 재서 높이 구간 x 폼별 상한을 잡았다(잰 상한에서
     한 칸씩 내려서):
       ≥1000px : 전부 1.6
       850~999 : 기본 1.35 · 참가 1.3 · 만들기 1.25
       ≤849px  : 기본 1.2  · 참가 1    · 만들기 1
     ⚠️ **도구가 이 문제를 못 봤다.** measureLobby가 .stage-form만 재고 카드 안쪽은
       재지 않았고, 게다가 **규칙을 펼친 상태만** 측정해 "펼치면 스크롤은 정상"에
       묻혔다. 세 가지를 고쳤다 — 카드스크롤 칸 추가, 접힌 상태(solo@/create@/join@)
       측정 추가, 가장 빠듯한 **1366x768을 뷰포트에 추가**.
     · "펼치기>접기 하면 사라진다"는 헤드리스에서 재현되지 않았다(계속 남아 있었다).
       다만 넘침 자체가 실재했고 이제 0이므로 그 증상도 함께 없어진다.

   3 — 로비 폼(.lobby-form-board)과 대기실을 가른 두 장으로 교체.
     **이 교체가 2번 해결에 결정적이었다** — 합본은 원본 PNG의 투명 여백을 되돌리느라
     액자를 상자 밖으로 --board-mt/mb(35px)만큼 밀어야 했고 그만큼 카드의 최대 높이에서
     미리 빼고 있었다. 가른 그림은 여백이 없어 그 35px이 카드 높이로 돌아왔다.
     레이아웃이 어긋나지 않게 안여백은 전과 같은 자리에 맞췄다 —
       로비 폼 29px(기존 29.4, --board-edge 16 + --board-inner-pad 13)
       대기실  28px(기존 27.4, 20 + 8 · .waiting-board)
     양피지는 **승패 화면만 0.82이고 나머지는 불투명(1)** — 입력칸·참가자 목록·채팅처럼
     계속 읽고 고치는 자리는 배경이 비치면 글자가 흔들려 보인다.
     ⚠️ back_board.png(444KB)는 이제 아무 화면도 쓰지 않는다. BoardFrame의 비-split
       기본 경로에만 남아 있는데 public/ui가 통째로 프리로드 대상이라 **로딩 화면이
       444KB를 그냥 받아온다.** 지우라는 말이 없어 두었다.

   4 — 원인이 둘이었다.
     (a) **왼쪽 위 한 장만 다른 그림이었다.** 연결 성분으로 뜯어보니 howto_corner_tl만
       잉크가 캔버스 안쪽 68px 오른쪽 · 27px 아래에서 시작하고 양도 적었다
       (잉크 8.1% vs 나머지 10~13%). 나머지 셋은 캔버스 모서리에 닿는다. 그래서 덩굴이
       액자를 놓치고 양피지 위에 떠 있었고, **크기를 키우면 어긋남이 함께 커져** 글자
       위로 파고들었다 — 크기로는 못 고치는 문제다. 오른쪽 위를 좌우 반전해 다시
       만들었다(scripts/mirrorHowtoCornerTL.mjs, 원본은 assets-src에 보존).
     (b) **크기가 px 고정이라 뷰포트마다 비중이 달랐다.** 162px 고정인데 창은 넓은
       화면에서 922px, 좁은 화면에서 364px까지 줄어 판 폭의 **17.6% vs 28.3%**였다
       (좁은 화면만 따로 103px로 잡아 둔 것이 그 증거였다). --howto-orn: 26.5%로 바꿔
       한 값이 모든 폭에서 같은 비중을 지키게 하고(데스크톱 162 → 약 257px) 좁은 화면
       예외는 지웠다.

   확인 — 검증용 프로덕션 빌드로 measureLobby **4뷰포트 x 10상태 = 40건 문제 없음**,
   대기실 안쪽 스크롤 138px(기존 137), 승패 화면 양피지 0.82 · 세로넘침 0)

참고 — 새 PC 환경 구성

· 루트에서 npm install 한 번이면 워크스페이스 셋이 다 걸린다(node_modules/shared
  심링크 확인). 서버는 cd server && npm run dev(8080), 클라이언트는
  cd client && npm run dev(3000)로 **각각 별도 터미널**.
· sharp의 install 스크립트가 승인되지 않아 건너뛰어진다. 에셋 자르기 스크립트
  (cutMedals·cutBackBoard·cutPlaySheet·cutHands·mirror*)에서만 쓰므로 게임 실행에는
  지장이 없지만, **이 날 쓴 스크립트들은 sharp가 필요하다** —
  npm install-scripts approve sharp 후 재설치.
· 이 날 Turbopack이 낡은 CSS 청크를 계속 내주는 일이 **네 번** 있었다. 증상은 늘 같다
  — 코드는 고쳤는데 화면·실측이 옛 값이다. cd client && npm run dev:clean.
  ⚠️ dev 서버를 껐다 켜는 것만으로는 안 고쳐진다. 그리고 **포트 3000을 잡고 있는 낡은
  프로세스를 먼저 죽여야 한다** — 안 그러면 새 dev가 3001로 밀려나거나
  "Another next dev server is already running"으로 죽는다.
· 검증용 빌드를 파이프로 받을 때 `next build | tail`의 종료 코드는 **tail의 것**이다.
  빌드가 실패해도 && 뒤가 그대로 돌아 낡은 .next-verify를 서빙했고, 청크가 500으로
  떨어져 measureLobby가 30초 타임아웃으로 죽었다. ${PIPESTATUS[0]}로 확인할 것.

참고 — 이 날 배운 것
══════════════════════════════════════════════
· **화면에 뜬 초록 띠를 장식으로 의심하기 전에 스크롤바인지 보라.** 이 프로젝트는
  스크롤바 손잡이를 초록 알약으로 칠해 두었고 hover하면 세 배로 굵어진다.

· **overflow-y-auto는 가로축까지 켠다.** 한 축이 visible이 아니면 다른 축의 visible이
  auto가 되는 것이 규정이다. 세로만 스크롤시키려면 가로를 명시적으로 막아야 한다.

· **clip은 hidden이 될 수 있다.** 다른 축이 auto면 clip이 hidden으로 계산되고
  overflow-clip-margin은 효력을 잃는다 — 넘침을 용서해 주지 않는다.

· **회전한 장식은 지정한 값보다 넓게 차지한다.** rotate(-12deg)가 배지 상자를 한쪽당
  약 3px 넓혔고 그것이 안여백을 넘겼다. 걸침 폭을 정할 때 회전분을 함께 셀 것.

· **같은 변수 이름이라도 그림이 바뀌면 뜻이 바뀐다.** --board-edge는 합본에서 "슬라이스
  두께"였지만 바짝 자른 그림에서는 "나무 두께" 그 자체다. 그림을 갈 때 숫자를 그대로
  물려받지 말 것.

· **정확히 N px 옮기려면 transform이다.** justify-center 안에서는 높이가 바뀌는 순간
  전체가 다시 가운데로 맞춰져 margin은 절반만 듣는다.

· **한 배율을 여러 폼이 함께 쓰면 가장 긴 것이 먼저 터진다.** 내용 높이가 다른 화면은
  상한도 따로 두어야 한다.

· **재지 않는 상자는 없는 것과 같다.** 카드 안쪽 스크롤을 재지 않아서, 화면에 막대가
  떠 있는데도 도구가 오래 "문제 없음"이라고 말했다. **접힌 기본 상태를 먼저 재고**,
  가장 빠듯한 해상도를 뷰포트에 넣을 것.

· **네 장 세트는 한 장이 다를 수 있다.** 크기만 만지기 전에 잉크의 경계상자와 양을
  네 장 모두 재서 견줄 것 — 어긋난 그림은 키울수록 더 어긋난다.

· **고정 px 장식은 창이 늘어나면 비중이 달라진다.** 좁은 화면용 예외값이 따로 있다면
  그것이 곧 "%로 두었어야 한다"는 신호다.

· **paint-order: stroke fill 없이 글자에 외곽선을 두르지 말 것.** 작은 글씨의 속이
  메워진다.

· **sharp는 부르는 차례가 아니라 정해진 차례로 처리한다**(extract → resize → extend).
